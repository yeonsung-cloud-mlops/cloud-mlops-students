## 2. 이론 (45분)

### 2-1. 모델보다 데이터 (10분)

**강의 스크립트**
> 질문 하나 드리겠습니다. 여러분이 예측 정확도를 5%p 올려야 합니다. 딱 하루가 주어졌습니다. 뭘 하시겠습니까?
> (학생 답 유도 — 모델 바꾼다, 하이퍼파라미터 튜닝한다, 딥러닝으로 간다 …)
> 대부분 모델 얘기를 하십니다. 그런데 실무에서 답은 거의 항상 **데이터**입니다.
>
> 이유를 하나만 들겠습니다. 모델을 랜덤포레스트에서 XGBoost로 바꾸면 보통 몇 % 좋아질까요? 잘 되면 1~2%p입니다. 그런데 **"결측값이 -1로 채워져 있던 걸 발견해서 고쳤더니"** 10%p가 올라갑니다. 실제로 이런 일이 훨씬 흔합니다.
> 그래서 실무에서 데이터 관련 일에 쓰는 시간이 전체의 압도적 다수입니다. 모델 코드는 정말 몇십 줄입니다. 4주차에 직접 보시게 됩니다.
>
> 구체적인 예를 하나 들겠습니다. 따릉이 대여량 데이터에 이런 게 섞여 있다고 칩시다.
> - 대여 건수가 `-1` 인 행 → 이건 "0건"일까요, "측정 실패"일까요? **둘은 완전히 다릅니다.**
> - 기온이 `999.0` 인 행 → 센서 고장 표시입니다. 이걸 그대로 학습시키면 모델이 "기온 999도일 때 대여량 폭증"을 배웁니다.
> - 강수량 칸이 비어 있는 행 → 비가 안 왔다는 뜻일 수도 있고, 관측소가 안 보낸 걸 수도 있습니다.
>
> 이런 걸 안 보고 모델부터 돌리면, 정확도 92%가 나와도 **그 92%가 뭘 의미하는지 아무도 모릅니다.**
> 이 과목이 정확도로 점수를 안 준다고 첫 주에 말씀드렸죠. 대신 **"당신 데이터에 뭐가 들어있는지 아는가"**를 봅니다. 그게 오늘 만들 데이터 카드입니다.

**판서/슬라이드 요점**
- 성능을 가르는 건 모델 교체가 아니라 **데이터 품질**인 경우가 압도적으로 많다
- 흔한 함정 3종: **의미 있는 이상값**(`-1`, `999`), **결측의 의미 구분**(0인가 미측정인가), **단위·시간대 불일치**
- 데이터를 보지 않고 얻은 정확도는 설명할 수 없다
- 이 과목의 평가 기준: 정확도가 아니라 **재현성 + 설명 가능성**

**학생 질문 예상 & 답변**
- Q: 결측값은 그냥 평균으로 채우면 되지 않나요? → A: 그게 답인 경우도 있고 아닌 경우도 있습니다. **"왜 비었는가"를 먼저 봐야** 합니다. 센서 고장으로 빈 거면 평균으로 채워도 되지만, "그날 운영을 안 했다"라서 빈 거면 0이 맞습니다. 판단 근거를 데이터 카드에 적는 게 오늘 과제입니다.
- Q: 이상치는 무조건 지우나요? → A: 아닙니다. 이상치가 **우리가 예측하려는 대상**일 수도 있습니다. 불량 탐지 프로젝트에서 이상치를 지우면 예측할 게 없어집니다. 도메인을 보고 판단합니다.

### 2-2. 데이터 저장 규칙: `raw/` → `processed/` → `features/` (10분)

**강의 스크립트**
> 1주차에 폴더 세 개를 만들라고 했죠. 오늘 그 이유를 제대로 말씀드리겠습니다.
>
> 규칙은 딱 하나입니다. **`raw/`는 성역입니다. 절대 수정하지도, 덮어쓰지도, 삭제하지도 않습니다.**
> 왜냐고요? 상황을 하나 상상해 봅시다. 여러분이 원본 CSV를 열어서 이상한 행 몇 개를 지우고 저장했습니다. 그리고 3주 뒤에 "어? 결과가 이상한데?" 싶어서 돌아왔습니다. **뭘 지웠는지 기억나십니까?** 안 납니다. 그리고 되돌릴 방법이 없습니다.
> 원본을 그대로 두면 언제든 처음부터 다시 할 수 있습니다. **원본은 진실의 기준점**입니다.
>
> 그래서 데이터가 이렇게 흘러갑니다.
>
> ```
> raw/          받은 그대로. 손대지 않음. 읽기 전용.
>   │  preprocess.py  ← 결측·이상치 처리, 타입 변환, 파생변수
>   ▼
> processed/    분석·학습에 바로 쓸 수 있는 상태. 스크립트로만 생성됨.
>   │  build_features.py  ← 인코딩, 스케일링, 집계 (4~5주차)
>   ▼
> features/     모델 입력 직전 형태 (숫자 행렬)
> ```
>
> 화살표에 붙은 게 **스크립트**라는 게 중요합니다. 사람 손이 아니라 코드가 데이터를 옮깁니다.
> 이게 되면 뭐가 좋을까요? **`processed/` 폴더를 통째로 지워도 아무 문제가 없습니다.** 스크립트를 다시 돌리면 똑같은 게 나오니까요.
> 반대로, 지웠는데 다시 못 만드는 폴더가 있다면 그건 뭔가 잘못된 겁니다. 그 폴더에 "사람이 손으로 한 작업"이 숨어 있다는 뜻이거든요.
>
> 파일 이름 규칙도 하나 정하고 가겠습니다. 나중에 파일이 30개쯤 되면 이게 생명입니다.
> `<데이터셋명>_<기간>_<처리단계>.csv` — 예: `bike_rental_2024_processed.csv`
> `최종.csv`, `최종_진짜최종.csv`, `최종_진짜최종_v2.csv` 이런 거 만들지 마세요. 여러분 팀원이 웁니다.

**판서/슬라이드 요점**
- `raw/` = **읽기 전용 성역.** 수정·덮어쓰기·삭제 금지
- `processed/` = 정제 완료. **스크립트로만 생성.** 지워도 재생성 가능해야 정상
- `features/` = 모델 입력 직전 (4~5주차부터 사용)
- 화살표는 **사람 손이 아니라 스크립트**여야 한다 → 이것이 재현성
- 파일명 규칙: `<데이터셋>_<기간>_<단계>.csv` · "최종_진짜최종" 금지

**학생 질문 예상 & 답변**
- Q: `processed/`에 있는 걸 조금만 손으로 고치면 안 되나요? → A: 그 순간 재현성이 깨집니다. 고쳐야 할 게 있으면 **스크립트를 고치고 다시 돌리세요.** 지금은 귀찮지만 4주차부터 이게 여러분을 살립니다.
- Q: 원본이 500MB인데 매번 다 읽으면 느리지 않나요? → A: 느립니다. 그래서 실무에서는 `processed/`를 CSV 대신 **Parquet** 같은 형식으로 저장합니다. 우리 수업 데이터는 작아서 CSV로 충분하지만, 관심 있으면 `df.to_parquet()`을 써보세요. (`pyarrow`를 2주차에 설치해뒀습니다)

### 2-3. 문제를 ML 문제로 바꾸기 (15분)

**강의 스크립트**
> 이제 오늘의 진짜 핵심입니다. 여러분이 4주차에 낼 M1 문제정의서가 여기서 나옵니다.
>
> 학생들이 프로젝트 주제를 이렇게 씁니다. **"따릉이 데이터로 뭔가 재밌는 걸 해보겠습니다."**
> 이건 주제가 아닙니다. 이 상태로는 모델을 만들 수도 없고, 잘했는지 못했는지 판단할 수도 없습니다.
>
> 주제를 ML 문제로 바꾸려면 **세 가지 질문**에 답해야 합니다. 딱 세 개입니다.
>
> **질문 1. 입력이 무엇인가?** — 예측하는 순간에 **실제로 알 수 있는 정보**만 입력이 될 수 있습니다.
> 이게 함정입니다. "내일 대여량을 예측하겠다"면서 입력에 "내일 실제 기온"을 넣으면 안 됩니다. 내일 기온은 내일 가봐야 압니다. **예보값**을 써야 합니다.
> 이런 실수를 **데이터 누수(leakage)** 라고 하고, 4주차에 자세히 다룹니다. 오늘은 "예측 시점에 알 수 있는가?"만 자문하세요.
>
> **질문 2. 출력이 무엇인가?** — 숫자 하나인가, 분류 라벨인가, 아니면 여러 개인가?
> 숫자를 맞히면 **회귀**, 어느 그룹인지 맞히면 **분류**입니다. 우리 도메인 A는 회귀, B는 분류, C는 분류 + 생성입니다.
> 그리고 **출력의 단위와 범위**까지 적어야 합니다. "대여량"이 아니라 "**해당 시간(1시간) 동안의 대여 건수, 0 이상의 정수**"라고 적어야 합니다.
>
> **질문 3. 무엇으로 잘했다고 판단하나?** — 평가지표입니다.
> 여기서 학생들이 습관적으로 "정확도"를 씁니다. 그런데 회귀에는 정확도가 없습니다. 그리고 분류에서도 정확도가 위험할 때가 많습니다.
> 예를 들어 불량품이 1%인 공정에서, "전부 정상"이라고 찍는 모델의 정확도는 몇 %일까요? **99%입니다.** 아무것도 안 하는 모델이 99점을 받습니다. 그래서 이런 경우엔 F1이나 재현율(Recall)을 씁니다.
>
> | 문제 유형 | 주로 쓰는 지표 | 언제 |
> |---|---|---|
> | 회귀 | RMSE, MAE | 값의 오차 크기가 중요할 때 |
> | 회귀 | MAPE | 오차를 % 로 말해야 할 때 |
> | 분류 (균형) | Accuracy, F1 | 클래스가 고르게 있을 때 |
> | 분류 (불균형) | F1, Recall, PR-AUC | 소수 클래스가 중요할 때 (불량·이탈·사기) |
>
> 마지막으로 하나 더. **성공 기준**을 숫자로 적어야 합니다. "잘 되면 좋겠다"가 아니라 "**RMSE 15 이하**", "**F1 0.75 이상**" 처럼요.
> 그럼 그 숫자는 어디서 나올까요? **베이스라인**에서 나옵니다. 예를 들어 "지난주 같은 시간의 값을 그대로 답으로 쓰기"라는 무식한 방법의 RMSE가 20이라면, 우리 모델은 최소 20보다는 나아야 존재 이유가 있는 겁니다. 4주차에 이 베이스라인을 직접 만듭니다.
>
> 정리하겠습니다. 오늘 여러분 팀이 채워야 할 문장은 이겁니다.
> **"[입력]을 받아서 [출력]을 예측하고, [평가지표]로 [성공기준] 이상이면 성공이다."**

**판서/슬라이드 요점**
- ML 문제 = **입력 / 출력 / 평가지표 / 성공기준** 네 칸 채우기
- 입력 조건: **예측 시점에 실제로 알 수 있는 값만** (아니면 데이터 누수)
- 출력: 숫자면 회귀, 라벨이면 분류. **단위와 범위까지** 명시
- 지표: 회귀 = RMSE/MAE, 불균형 분류 = F1/Recall (정확도 함정 주의)
- 성공기준은 **베이스라인 대비 숫자로**
- 한 문장 템플릿: "[입력]을 받아 [출력]을 예측하고, [지표]로 [기준] 이상이면 성공"

**학생 질문 예상 & 답변**

**③ 전처리 스크립트 작성 (25분)**

이제 노트북에서 실험한 것을 **하나의 스크립트**로 옮긴다. `preprocess_skeleton.py` 의 `# TODO` 부분만 채운다.

JupyterLab에서 `~/work/w03/preprocess.py` 를 만들고 아래를 작성한다. (골격은 배포되어 있고, **TODO 표시된 5곳만 학생이 직접 입력**한다)

```python
"""
w03 전처리 스크립트
raw/ 의 원본을 읽어 정제·파생변수 생성 후 processed/ 에 저장한다.
원본은 절대 수정하지 않는다.

실행:  python preprocess.py
"""
import sys
import time
import pandas as pd
import numpy as np

# ─────────────────────────────────────────────
# 설정 — 본인 버킷 이름으로 바꿀 것
BUCKET   = "mlops-2026-<학번>"
RAW_KEY  = "raw/bike_rental_2024.csv"
OUT_KEY  = "processed/bike_rental_2024_processed.csv"

RAW_PATH = f"s3://{BUCKET}/{RAW_KEY}"
OUT_PATH = f"s3://{BUCKET}/{OUT_KEY}"
# ─────────────────────────────────────────────


def load(path: str) -> pd.DataFrame:
    """[1/5] 원본 읽기"""
    df = pd.read_csv(path)
    print(f"[1/5] load    : {path}  (rows={len(df):,})")
    return df


def clean(df: pd.DataFrame) -> pd.DataFrame:
    """[2/5] 결측·이상치 처리"""
    before = len(df)
    df = df.copy()                      # ★ 원본 DataFrame을 건드리지 않는다

    # (1) 날짜 타입 변환
    df["rent_dt"] = pd.to_datetime(df["rent_dt"], errors="coerce")
    df = df.dropna(subset=["rent_dt"])

    # (2) TODO ①: 센서 오류값을 결측으로 바꾼다
    #     temp_c 가 900 이상이면 NaN 으로
    df.loc[df["temp_c"] >= 900, "temp_c"] = np.nan

    # (3) TODO ②: 목표 변수의 음수(-1 = 미집계)는 행 자체를 버린다
    #     이유: 목표 변수를 임의 값으로 채우면 모델이 가짜 패턴을 배운다
    df = df[df["rental_count"] >= 0]

    # (4) TODO ③: 강수량 결측은 0으로 채운다
    #     이유: 관측소 미보고 = 무강수로 판단 (데이터 카드에 근거를 남길 것)
    df["precip_mm"] = df["precip_mm"].fillna(0.0)

    # (5) TODO ④: 기온·습도 결측은 시간 순서상 앞뒤 값으로 보간한다
    #     이유: 기상값은 연속적으로 변하므로 직전 값이 합리적 추정치
    df = df.sort_values("rent_dt")
    df["temp_c"]   = df["temp_c"].interpolate(limit_direction="both")
    df["humidity"] = df["humidity"].interpolate(limit_direction="both")

    # (6) 중복 행 제거
    df = df.drop_duplicates()

    # (7) 극단 이상치: 대여 건수 상위 0.1% 는 잘라낸다
    cap = df["rental_count"].quantile(0.999)
    n_out = (df["rental_count"] > cap).sum()
    df = df[df["rental_count"] <= cap]

    # 남은 결측이 없는지 확인
    assert df.isna().sum().sum() == 0, f"결측 남음:\n{df.isna().sum()}"

    print(f"[2/5] clean   : {before - len(df):,}행 제거/처리 "
          f"(이상치 {n_out}행 포함) → rows={len(df):,}")
    return df


def add_features(df: pd.DataFrame) -> pd.DataFrame:
    """[3/5] 파생변수 생성"""
    df = df.copy()

    # 시간 관련 파생변수 — 시계열 예측의 기본
    df["hour"]       = df["rent_dt"].dt.hour
    df["weekday"]    = df["rent_dt"].dt.weekday          # 0=월 ... 6=일
    df["month"]      = df["rent_dt"].dt.month
    df["is_weekend"] = (df["weekday"] >= 5).astype(int)

    # TODO ⑤: 출퇴근 시간대 표시 변수를 만든다
    #     7~9시 또는 18~20시면 1, 아니면 0
    df["is_rush"] = df["hour"].isin([7, 8, 9, 18, 19, 20]).astype(int)

    # 기온 구간화 (범주형 파생변수 예시)
    df["temp_bin"] = pd.cut(
        df["temp_c"],
        bins=[-50, 0, 10, 20, 30, 50],
        labels=["매우추움", "추움", "선선", "따뜻", "더움"],
    ).astype(str)

    # 비가 왔는지 여부
    df["is_rain"] = (df["precip_mm"] > 0).astype(int)

    new_cols = ["hour", "weekday", "month", "is_weekend",
                "is_rush", "temp_bin", "is_rain"]
    print(f"[3/5] feature : {', '.join(new_cols)} 생성")
    return df


def save(df: pd.DataFrame, path: str) -> None:
    """[4/5] processed/ 에 저장"""
    df.to_csv(path, index=False)
    print(f"[4/5] save    : {path}")


def summarize(df: pd.DataFrame) -> None:
    """[5/5] 요약 출력 — 데이터 카드에 붙여넣을 내용"""
    print(f"[5/5] summary : rows={len(df):,}  cols={df.shape[1]}")
    print("        기간:", df['rent_dt'].min(), "~", df['rent_dt'].max())
    print("        목표변수 rental_count  평균 %.2f / 최대 %d"
          % (df['rental_count'].mean(), df['rental_count'].max()))


def main() -> int:
    t0 = time.time()
    df = load(RAW_PATH)
    df = clean(df)
    df = add_features(df)
    save(df, OUT_PATH)
    summarize(df)
    print(f"done in {time.time() - t0:.1f}s")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

**4단계 · 문제정의서 초안 작성 (30분)**

부록 C 양식(`problem_statement_template.md`)을 팀 문서로 복사해 채운다. 파일명은 `problem_statement_T<NN>.md`.

**작성 순서 — 이 순서대로 채워야 막히지 않는다**
1. **출력부터** 정한다. "우리가 맞히려는 값 하나"를 문장으로 쓴다. (단위·범위 포함)
2. 그 값이 **데이터의 어느 컬럼인지** 지목한다. 없으면 만들 수 있는지 본다. 못 만들면 데이터를 바꾼다.
3. **입력**을 나열한다. 각 입력에 대해 "**예측 시점에 이 값을 알 수 있는가?**"를 자문하고, 아니면 지운다.
4. **평가지표**를 고른다. (회귀 → RMSE/MAE, 불균형 분류 → F1/Recall)
5. **성공 기준**을 숫자로 잠정 기재한다. (4주차 베이스라인 이후 조정)
6. 마지막에 **한 문장 요약**을 쓴다.

**한 문장 요약 템플릿**
```text
우리는 [입력: 시간·날씨·대여소 정보]를 받아
[출력: 해당 대여소의 다음 1시간 대여 건수(0 이상 정수)]를 예측하고,
[지표: RMSE]로 [기준: 15 이하]이면 성공으로 본다.
```

**순회 시 강사가 던지는 질문 3개** (팀마다 반드시 물어본다)
1. "그 입력값, **예측하는 순간에 진짜로 알 수 있습니까?**"
2. "정답 라벨이 **데이터의 어느 컬럼**입니까? 손으로 짚어보세요."
3. "이 데이터, **지금 다운로드 받아서 열어봤습니까?** 화면 보여주세요."

### 팀 프로젝트 연결

- 오늘 작성한 **문제정의서 초안 = M1(4주차 제출, 10점)의 골격**이다. 4주차에는 베이스라인 성능을 붙여 최종본으로 만든다.
- 오늘 확보한 데이터가 **12주 내내 쓰는 데이터**다. 오늘 잘못 고르면 5주차쯤 갈아엎게 되고, 그게 매년 실패의 1번 원인이다.
- 실습 A에서 만든 `preprocess.py` 는 **팀 데이터용으로 그대로 복제해 쓴다.** 컬럼명과 정제 규칙만 바꾼다. (설계 원칙: "같은 골격에 자기 데이터만 갈아 끼운다")
- 오늘 채운 **데이터 카드**는 M1 제출물의 필수 구성 요소다.
- 팀 태그(`Team=T<NN>`)는 학기 내내 비용 추적에 쓰인다. 반드시 갱신한다.

### 순회 지도 포인트

강사·조교가 돌아다니며 확인할 것 3가지.

1. **데이터를 실제로 다운로드해서 열어봤는가.** 화면에 `df.head()` 결과가 떠 있는지 눈으로 본다. "받을 수 있을 것 같아요"는 인정하지 않는다.
2. **목표 변수(라벨)를 컬럼으로 지목할 수 있는가.** 못 지목하는 팀은 그 자리에서 데이터를 바꾸게 한다. 늦어질수록 손해가 커진다.
3. **입력에 미래 정보가 섞이지 않았는가.** "내일 대여량을 예측하는데 입력에 내일 실제 기온" 같은 것. 발견하면 그 자리에서 지적하고 데이터 누수 개념을 짧게 설명한다.

추가 확인: 자유주제(D) 팀은 승인 조건 5개를 전부 확인받았는지, 팀 태그를 갱신했는지 본다.

```python
# ══ 4. pandas 데이터 점검 5줄 (새 데이터 만나면 무조건 이것부터) ══
import pandas as pd
df = pd.read_csv("s3://mlops-2026-<학번>/raw/data.csv")   # 한글깨짐 → encoding="cp949"

df.shape                      # (행, 열)
df.columns.tolist()           # 컬럼 이름 목록
df.info()                     # 타입 + 결측 개수
df.isna().mean().round(3)*100 # 컬럼별 결측 비율(%)
df.describe().T               # 숫자 요약 ★ 여기서 -1, 999 가 잡힌다
df.duplicated().sum()         # 중복 행 개수
df["목표컬럼"].value_counts()  # 분류 문제면 클래스 균형 확인

# ══ 5. 결측 처리 ══════════════════════════════════════
df["col"] = df["col"].fillna(0)                       # 상수로 채우기
df["col"] = df["col"].fillna(df["col"].median())      # 중앙값으로
df["col"] = df["col"].interpolate(limit_direction="both")  # 앞뒤 값으로 보간
df = df.dropna(subset=["목표컬럼"])                    # 목표 변수 결측은 행 제거

# ══ 6. 이상치 처리 ════════════════════════════════════
import numpy as np
df.loc[df["temp_c"] >= 900, "temp_c"] = np.nan        # 센서 오류값 → 결측으로
df = df[df["rental_count"] >= 0]                      # 음수 제거
cap = df["col"].quantile(0.999)                       # 상위 0.1% 절단
df = df[df["col"] <= cap]
df = df.drop_duplicates()                             # 중복 제거

# ══ 7. 파생변수 만들기 ════════════════════════════════
df["dt"]         = pd.to_datetime(df["dt"], errors="coerce")
df["hour"]       = df["dt"].dt.hour
df["weekday"]    = df["dt"].dt.weekday       # 0=월 ... 6=일
df["month"]      = df["dt"].dt.month
df["is_weekend"] = (df["weekday"] >= 5).astype(int)
df["is_rush"]    = df["hour"].isin([7,8,9,18,19,20]).astype(int)
df["temp_bin"]   = pd.cut(df["temp_c"], bins=[-50,0,10,20,30,50],
                          labels=["매우추움","추움","선선","따뜻","더움"]).astype(str)

# ══ 8. 저장 ═══════════════════════════════════════════
df.to_csv(f"s3://{BUCKET}/processed/data_processed.csv", index=False)
df.to_parquet(f"s3://{BUCKET}/processed/data_processed.parquet", index=False)  # 더 빠름
```

1. `raw/` 는 읽기만 한다. 절대 덮어쓰지 않는다.
2. 처리는 **스크립트**로 한다. 두 번 돌려 같은 결과가 나와야 한다.
3. 무엇을 바꿨으면 **왜 바꿨는지**를 데이터 카드에 적는다.

## 부록 D. 용어 정리

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| 데이터 파이프라인 | 데이터가 흘러가는 경로 | `raw/` → `processed/` → `features/`. 각 화살표는 **스크립트** |
| `raw/` | 원본 보관소 | **읽기 전용 성역.** 수정·덮어쓰기·삭제 금지 |
| `processed/` | 정제 완료 데이터 | 스크립트로만 생성. 지워도 재생성 가능해야 정상 |
| `features/` | 모델 입력 직전 형태 | 인코딩·스케일링 완료. 4~5주차부터 사용 |
| 재현성 (Reproducibility) | 같은 입력 → 같은 결과 | 스크립트를 두 번 돌려 결과가 같으면 확보된 것 |
| 결측값 (Missing value) | 비어 있는 값 | pandas에서는 `NaN`. **"왜 비었는가"를 먼저 본다** |
| 이상치 (Outlier) | 범위를 벗어난 값 | `-1`, `999` 같은 **코드값**일 수도, 진짜 극단값일 수도 |
| 보간 (Interpolation) | 앞뒤 값으로 빈칸 채우기 | 시간에 따라 연속적으로 변하는 값(기온 등)에 적합 |
| 파생변수 (Derived feature) | 기존 컬럼에서 새로 만든 컬럼 | `hour`, `is_weekend`, `is_rush` 등 |
| 구간화 (Binning) | 연속값을 구간으로 나누기 | `pd.cut()`. 기온 → 매우추움/추움/선선/따뜻/더움 |
| 목표 변수 (Target) | 맞히려는 값 | 라벨(label), 종속변수라고도 함 |
| 입력 변수 (Feature) | 맞히는 데 쓰는 값 | 독립변수, 설명변수라고도 함 |
| 회귀 (Regression) | 숫자를 맞히는 문제 | 대여량, 가격, 수요 등. 지표는 RMSE/MAE |
| 분류 (Classification) | 어느 그룹인지 맞히는 문제 | 이탈/유지, 불량/정상. 지표는 F1/Recall |
| RMSE | Root Mean Squared Error | 오차 제곱 평균의 제곱근. 큰 오차에 민감 |
| MAE | Mean Absolute Error | 오차 절댓값 평균. 해석이 직관적 |
| F1 | 정밀도와 재현율의 조화평균 | 클래스 불균형일 때 정확도 대신 쓴다 |
| Recall (재현율) | 실제 양성 중 맞힌 비율 | "놓치면 안 되는" 문제(불량·질병)에서 중요 |
| 클래스 불균형 | 한쪽 라벨이 압도적으로 많음 | 불량 1% 같은 경우. **정확도가 무의미해진다** |
| 데이터 누수 (Leakage) | 예측 시점에 알 수 없는 정보가 입력에 섞임 | 성능이 비정상적으로 높게 나오는 주범. 4주차 상세 |
| 베이스라인 (Baseline) | 비교 기준이 되는 단순한 방법 | "이보다 못하면 모델을 쓸 이유가 없다"의 기준선 |
| 데이터 카드 (Data Card) | 데이터의 신분증 | 출처·기간·규모·라이선스·개인정보·처리 이력 |
| 공공누리 | 공공데이터 이용 허락 표시 | 제1유형(출처표시)이 가장 개방적 |
| Parquet | 열 지향 저장 형식 | CSV보다 빠르고 작다. `df.to_parquet()` |
| `describe()` | 숫자 컬럼 요약 통계 | **새 데이터를 만나면 제일 먼저 돌린다.** min/max에서 이상치가 잡힌다 |
| `SettingWithCopyWarning` | 복사본을 수정할 때 뜨는 경고 | 필터링 후 `.copy()` 를 붙이면 사라진다 |
